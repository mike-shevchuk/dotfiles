Ти дописуєш запис на **спільну HTML-дошку** координації двох репозиторіїв навколо фічі «GoTo → Emergency: метадані». Дошку ведуть два агенти: **rescue-serverless** (приймач — зберігає/віддає `metadata`) і **workflow-engine** (продюсер — формує й шле declare).

**Файл дошки (абсолютний шлях):**
`/Users/mikeshevchuk/zettelkasten/claude_code/goto-emergency-metadata/board.html`

## Аргументи
`$ARGUMENTS` = `<роль> <текст>`, де:
- `<роль>` — перше слово: `rescue` (rescue-serverless), `wfe` (workflow-engine) або `mike` (оператор-людина; аліаси `me`/`op`).
  - Якщо роль не вказана, визнач сам за поточним репо: cwd містить `workflow-engine` → `wfe`; містить `rescue-serverless` → `rescue`; інакше запитай коротко, яку роль ставити.
- `<текст>` — решта: суть запису українською (що зроблено / знайдено / вирішено / що потрібно від іншої сторони).

Якщо `$ARGUMENTS` порожні — НЕ дописуй; натомість покажи, як переглянути дошку (нижче), і приклад виклику.

## Що зробити (append одного запису)
1. **Час:** виконай `date -u +"%Y-%m-%d %H:%M UTC"` (Bash) — це мітка запису. Не вигадуй час.
2. **Прочитай** файл дошки (Read), щоб не зламати структуру.
3. **Сформуй запис.** З `<текст>` виділи короткий заголовок (≤ ~70 симв.) і тіло. Тіло — 1–3 абзаци `<p>` та/або список `<ul><li>`, українською, читабельно. Технічні токени (`file:line`, id, шляхи, `code`) не перекладай, загортай у `<code>`.
   Роль → клас і бейдж:
   - `rescue` → `class="entry rescue"`, бейдж `<span class="who rescue">🔴 rescue-serverless</span>`
   - `wfe` → `class="entry wfe"`, бейдж `<span class="who wfe">🟣 workflow-engine</span>`
   - `mike` (аліаси `me`/`op`) → `class="entry mike"`, бейдж `<span class="who mike">🧑 Mike</span>`
   Шаблон запису:
   ```html
   <article class="entry РОЛЬ">
     <div class="m">БЕЙДЖ<time>ЧАС</time></div>
     <h3>ЗАГОЛОВОК</h3>
     <div class="body">ТІЛО</div>
   </article>
   ```
4. **Встав його НАГОРУ СВОЄЇ зони** (найновіше зверху). Дошка розділена на дві зони власності — обери маркер за роллю:
   - роль `rescue` → маркер `<!-- RESCUE:START -->` (у `<div class="zone rescue">`)
   - роль `wfe` → маркер `<!-- WFE:START -->` (у `<div class="zone wfe">`)
   - роль `mike`/`me`/`op` → маркер `<!-- MIKE:START -->` (у `<div class="zone mike">`)
   Зроби Edit, де `old_string` = цей маркер, а `new_string` = той самий маркер + новий рядок + твій `<article>…</article>`.
   **ПИШИ ЛИШЕ У СВОЮ ЗОНУ.** НІКОЛИ не чіпай чужу зону (інший маркер, чужі `<article>`), не видаляй маркери, і не редагуй спільні секції (Поточний стан / Схема даних / Payload — їх веде rescue). Чужу зону можна лише читати.
5. **Підтверди** одним рядком: що додав (роль + заголовок) і шлях до файлу.

## Перегляд дошки
Це локальний HTML-файл під коренем hub. Відкрити: `open <шлях>` (Bash) або `file://…`. По LAN його вже роздає ЄДИНИЙ bun-hub на фіксованому :8890 — переконайся, що він живий (`just -g hub-fix`), і дай URL `http://<lan-ip>:8890/goto-emergency-metadata/board.html`. НЕ піднімай окремий `python -m http.server`.

## Правила
- Один виклик = один запис. Не переписуй канонічні секції (схема даних / статус) — для змін статусу став новий запис у стрічку; канонічні секції правляться лише свідомо й окремо.
- Пиши по суті: що змінилось, що потрібно від іншої сторони, лінки на PR/тікети/`file:line`.
- Якщо додаєш новий ключ у спільну схему metadata — окремо онови таблицю «Спільна схема даних» у тому ж файлі й познач це в записі.
